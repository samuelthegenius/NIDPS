# NIDPS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rename NIPS → NIDPS, fix the audit findings, add demo-visible improvements, support host and gateway LAN modes, and make the project self-explanatory for a collaborator.

**Architecture:** The backend is split into small units built by factory functions (settings, IP/allowlist, Snort parser, store, firewall, detector, auth). `createApp(deps)` wires them, so every unit is tested with fakes via `node:test`. Firewall rules live in a dedicated `NIDPS` iptables chain, jumped to from `INPUT` (host mode) or `FORWARD` (gateway mode). In production the backend serves the built React app on the same port.

**Tech Stack:** Node 18+ (CommonJS, `node:test`, `crypto`, `net.BlockList`, `child_process.execFile`), Express 4, pg, tail; React 18 + Vite 5 + Tailwind 3; PostgreSQL 15; Snort 2.9.

**Spec:** `docs/superpowers/specs/2026-11-23-nidps-design.md`

## Global Constraints

- Name: "NIDPS" (Network Intrusion Detection and Prevention System) in all code, UI, DB (`nidps_db`), Docker (`nidps_postgres`, `nidps_pgdata`), log prefixes and docs. The working folder `Desktop\NIPS` is not renamed.
- No new runtime dependencies. Use Node built-ins.
- Must still run on Windows without PostgreSQL (memory store) and with a simulated firewall.
- No internet resources at runtime (no Google Fonts or CDNs).
- Errors returned to clients are generic; details are logged server-side only.
- Settings and their defaults: `PORT=5000`, `HOST=0.0.0.0`, `NIDPS_MODE=host|gateway` (host), `DEMO_MODE` (true in `.env.example`), `ENABLE_REAL_IPTABLES` (false), `WSL_DISTRO=Ubuntu-24.04`, `SNORT_LOG_PATH`, `SNORT_INTERFACE=eth0`, `NIDPS_ALLOWLIST` (comma-separated CIDRs/IPs), `BLOCK_DURATION_MIN=60` (0 = permanent), `ESCALATE_COUNT=5`, `ESCALATE_WINDOW_MIN=5`, `RETENTION_DAYS=30`, `ADMIN_USERNAME=admin`, `ADMIN_PASSWORD_HASH`, `SESSION_SECRET`, `TLS_CERT`, `TLS_KEY`, `DB_*`/`DATABASE_URL`.
- Session: HMAC-SHA256-signed cookie `nidps_session`, `HttpOnly; SameSite=Strict; Path=/`, `Secure` when TLS is on, 8 h TTL.
- Login rate limit: 5 failures per IP per 15 min → 429.
- Backend tests: `cd backend && npm test` (= `node --test test/`).

## Review Focus

1. **Two Priority‑1 alerts from the same IP arrive together.** Expected: one iptables rule and one active block row. → Task 4 test `concurrent blocks for same ip produce one rule`.
2. **Manual block of an allowlisted or own-interface IP.** Expected: refused with a clear 409 message; nothing is executed. → Task 4 test plus Task 7 HTTP test.
3. **Snort IPv6 endpoints without brackets** (`2001:db8::5:443`) and ICMP lines without ports. Expected: the correct IP is extracted. → Task 2 tests.
4. **Log file truncated by `npm run reset` while the watcher runs.** Expected: the watcher keeps ingesting new lines. → Task 5 test `continues after truncation`.
5. **Session expires while the dashboard is open.** Expected: the UI returns to the login screen once, without an error-toast flood. → Task 8 manual check plus the api.js `onUnauthorized` handler.

### Task 2: Snort parser

**Interfaces — Produces:** `parseSnortAlert(line: string, now: Date = new Date()) -> {timestamp: string(ISO), sid: string|null, source_ip, dest_ip, protocol, alert_message, classification, severity: 1..4} | null`. Status is no longer decided here.

Endpoint rule: if the whole token is a valid IP, use it. Otherwise, if it is `[v6]:port`, take the inside. Otherwise strip the last `:port` segment and accept it if what remains is a valid IP.

Timestamp rule: `MM/DD-HH:MM:SS(.ffffff)` is **local** time in `now`'s year. If the result is more than 1 day after `now`, use the previous year.

### Task 4: Firewall engine

**Files:**
- Create: `backend/src/services/firewall/commands.js`, `backend/src/services/firewall/index.js`
- Delete: `backend/src/services/firewall.js`
- Test: `backend/test/firewall.test.js`

**Interfaces:**
- Consumes: Store (Task 3), allowlist (Task 1), `isValidIp`/`normalizeIp`.
- Produces:
  - `buildCommands({mode, platform, wslDistro}) -> { setup(): Argv[], check(ip): Argv, block(ip): Argv, unblock(ip): Argv, flush(): Argv }`, where `Argv = [file, ...args]`. Linux: `['sudo','iptables',...]` (`['iptables',...]` when `process.getuid?.()===0`). Windows: `['wsl','-d',distro,'-u','root','iptables',...]`. Use `ip6tables` for IPv6. Chain `NIDPS`. `setup()` = `-N NIDPS` (error tolerated) and an `-I <INPUT|FORWARD> 1 -j NIDPS` jump guarded by `-C`. `block` = `-I NIDPS 1 -s ip -j DROP`. `unblock` = `-D NIDPS -s ip -j DROP`. `flush` = `-F NIDPS`.
  - `createFirewall({settings, store, allowlist, run = execFileAsync, events, now = () => new Date()}) -> { init(), block(ip, reason, actor) -> {status:'blocked'|'already'|'protected', block?}, unblock(ip, actor) -> {status:'unblocked'|'not_blocked'}, sweepExpired() -> number, list(activeOnly), mode, simulated }`. Throws `FirewallError` with `code: 'INVALID_IP'|'EXEC_FAILED'`.
  - `init()` runs setup, then re-applies every active non-expired block from the store (resync after reboot).
  - Simulated mode (`!settings.realFirewall`) logs argv and never calls `run`.
  - Every block/unblock writes audit (`action: 'block'|'unblock'|'block_refused'`) and emits `events.publish('block'|'unblock', record)`.
  - Per-IP promise lock (`Map<ip, Promise>`), so concurrent calls serialise.

- [ ] **Step 1: Failing tests** (fake `run` records argv; memory store):
  - `buildCommands({mode:'gateway',platform:'linux'}).setup()` includes `['-I','FORWARD','1','-j','NIDPS']`; host mode includes `INPUT`.
  - Windows block argv starts `['wsl','-d','Ubuntu-24.04','-u','root','iptables']`.
  - IPv6 block uses `ip6tables`.
  - `block('1.2.3.4; reboot')` rejects with `code 'INVALID_IP'`; `run` is never called.
  - `block('127.0.0.1')` → `status 'protected'`, no `run`, audit row `block_refused`.
  - `block` sets `expires_at = now + 60 min`; with `blockDurationMin 0` → `null`.
  - **`concurrent blocks for same ip produce one rule`**: `Promise.all([block(x), block(x)])` → exactly one block argv and one active row.
  - `sweepExpired()` unblocks the expired block and leaves the unexpired one.
  - `init()` re-applies the 2 active blocks.
  - When `run` rejects on block → `EXEC_FAILED`, and no active row is stored.
  - Simulated mode: `run` is never called, and the result still has a stored block.
